Using STM32F4 series MCU as a loudspeaker processor

Mar 2020STM322 min readBy Thei Munten

On the bench is a bare STM32F4 board with nothing but a blinking LED. Before it can process a single sample, it has to be programmed, and that means learning a different kind of coding.

A different kind of processor

There is a lot of information out there about using MCUs like the Arduino, or more upscale M4 ARM Cortex chips like those from ST, as a process controller. Measuring things, controlling things. Google STM32F4 and you will find all kinds of how-tos for managing I²C or SPI data streams.

As audio engineers interested only in I²S, we are not that lucky. Don't confuse I²C with I²S. There are also references for I²C and AD/DA, but those are about analog sensor data. Not audio.

So, as a future reference, I am going to describe the long and arduous task of getting these things to process audio. This is not a step-by-step tutorial: you will need different places to get the required knowledge, but hopefully it will be of use to someone stumbling across. Bear in mind that the whole process took me about four months.

First steps

These are microcontrollers. They do not run an OS like a Raspberry Pi, and they are not DSPs, so you can't program them with a third-generation language like SigmaStudio. Think bare-metal programming. Think C.

So the first thing to do is get some knowledge of embedded C coding and make your first program. The MCU equivalent of 'Hello World' is a blinking LED. You could write your code in a text editor, but that is really die-hard old-school. Nowadays one uses an integrated development environment as a helping hand.

Spend some time choosing an IDE that will serve the purpose. There is quite some free stuff out there; check PlatformIO or Eclipse-based applications. One warning: these are all community supported, and as there isn't a huge audio community active on these platforms, you might find them not useful at all.

After unsuccessfully trying everything on both Windows and Linux, I finally decided to use a commercial product: ARM Keil µVision. That could cost you some substantial cash, but there is a limited demo version that might just be enough for your purpose.
